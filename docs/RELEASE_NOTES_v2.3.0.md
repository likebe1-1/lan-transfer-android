# LanLink v2.3.0 发布说明

> 版本：v2.3.0（versionCode 11）
> 包名：com.manst.lantransfer（覆盖安装可直接保留数据）
> 发布日期：2026-11-21

## 本次重点

本次为**性能与安全**专项版本，无破坏性变更，覆盖安装即可。

### 1. 传输速度：队列改为 3 路有限并发
- 队列由「完全串行」改为**最多 3 个任务同时传输**；
- 大量小文件场景显著加速：每个文件的「连接 → 认证 → 断开」固定开销被并行摊薄；
- 每个任务仍使用**独立连接**，绝不共享；
- 失败重试的退避等待期间仍占用一个并发槽位，不会退化成忙重试；
- 如遇服务端限制并发连接数（部分 FTP 只允许 1~2 个会话），可在代码中把
  `TransferScheduler.DEFAULT_MAX_CONCURRENT_TASKS` 调为 1，退回原串行行为。

### 2. 传输速度：协议缓冲区调优
- **FTP/FTPS**：数据连接缓冲区设为 128 KiB（`setBufferSize` + 数据 socket 收发缓冲），
  原先默认仅 8 KiB；控制连接刻意不调（无吞吐收益）；
- **SFTP/SCP**：自有拷贝缓冲区 32 KiB → 128 KiB，作用于 SCP 线协议收发、目录读取与
  未知大小上传落盘；
- 说明：SFTP 的线上数据包尺寸由 JSch 库**硬编码为 32 KiB**，应用侧无法放大，
  因此 SFTP 单文件的线上分片不会变快（这是库的能力边界）。

### 3. 安全：服务端认证失败限流增强
- 新增**全局滑动窗口上限**（全服务 60 次失败/60 秒 → 冷却 30 秒），
  阻断攻击者「换 IP 水平爆破」绕过单 IP 限流；
- 新增**可信来源阶梯锁定**：最近 30 分钟内成功认证过的来源（典型为 NAT/CGNAT 后的正常设备）
  首次违规只锁 1 分钟、累犯 5 分钟、再犯 10 分钟，缓解误伤；**陌生来源仍锁满 10 分钟**，
  防护强度不下降；
- 冷却期间快速失败且不记账，攻击者 flood 无法撑大内存状态。

### 4. 安全：快速传文件证书/主机密钥指纹固定
- **FTPS**：证书指纹经二维码/广播下发，接收方只接受该指纹，中间人无法冒充；
  `allowInsecureTls` 降级为兼容旧配置的兜底，启用时打印安全警告；
- **SFTP/SCP**：发送方回传主机密钥 SHA-256 指纹，接收方固定校验
  （`StrictHostKeyChecking=yes`）；
- 无指纹的普通服务器仍退回首次信任，并在连接成功消息中提示。

### 5. 安全：服务器密码改用 Android Keystore 加密
- 服务器密码使用 **AES-256-GCM** 加密后写入 `servers.json`，密钥保存在 Android Keystore
  且**不可导出**，即使应用私有目录被拷走也无法解密；
- 每条密文随机 12 字节 IV；
- Keystore 异常时降级明文并记录日志（优先保证可用性）。

### 6. 更新清单签名
- `update.json` 使用 **Ed25519** 签名，App 内置公钥验签；镜像/代理即使篡改清单内容
  也无法伪造签名；
- 更新源强制 HTTPS；
- 下载的 APK 仍会再次校验 SHA-256 与 APK 签名（三重保障）。

### 7. 问题修复与工程改进
- 修正 `ARCHITECTURE.md` 中已过期的「已知限制」（主机密钥固定、Keystore 加密、断点续传、
  文件夹传输、局域网发现**均已实现**却仍列为未做）；
- 接收码展示分组对齐 8 位（`1234 5678`，旧版 6 位为 `123 456`）；
- proguard 规则由整包 keep 改为 `-keep,allowoptimization`，让 R8 优化重新生效；
- 清理误提交的构建日志并加固 `.gitignore`。

## 性能说明

本版本的速度提升主要来自「并发」与「缓冲区」，**不改变协议本身**：

| 场景 | 预期改善 |
| --- | --- |
| 大量小文件（几十个以上） | 明显（并发摊薄连接开销） |
| 单个大文件 FTP/FTPS | 中等（缓冲区 8 KiB → 128 KiB） |
| 单个大文件 SFTP | 有限（包尺寸受库限制） |
| 单个大文件 SCP | 中等（128 KiB 拷贝缓冲） |

## 已知限制
- 应用内更新依赖 GitHub/jsDelivr/镜像可访问；全部不可用时请使用蓝奏云浏览器下载；
- 一键组网需手动开启热点；热点信息读取在部分系统上会失败（可手动填写）；
- 本机服务器监听 `0.0.0.0`，依赖服务端认证限流兜底；多网卡/VPN 环境下请留意暴露面；
- SFTP 数据包尺寸受 JSch 未公开配置限制，无法从应用侧提升；
- Keystore 加密异常时会降级为明文保存（日志可查）。
