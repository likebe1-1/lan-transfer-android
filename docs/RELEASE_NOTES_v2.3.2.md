# LanLink v2.3.2 发布说明

> 版本：v2.3.2（versionCode 13）
> 包名：com.manst.lantransfer（覆盖安装可直接保留数据）
> 发布日期：2026-11-24

## 本次重点

v2.3.2 是性能专项 + 安全加固版本：大文件传输明显更快，同时补上三项移动端安全基线。功能与 v2.3.1 一致，无破坏性变更，可直接覆盖安装。

## 一、传输性能（核心）

### 1. 自动协议顺序改为 FTPS → SFTP → SCP
- FTPS 实测比 SFTP 快 1.5–3 倍，且已有证书指纹固定，安全性不降级；
- 明文 FTP 仍不参与自动选择，需用户手动指定。

### 2. 下载去掉「双重写盘」
- 以前先写缓存暂存文件、完成后整份复制到系统下载目录（同一份数据写两次）；
- 现在远端字节流直接写进 MediaStore 的 pending 文件，完成时只提交一次，零复制；
- 断点续传改为按 pending 文件的真实已写字节续传，语义更可靠。

### 3. 传输并发可配置（默认 3 → 5 路）
- 新增「传输设置」页（首页右上角），可调 1–6 路并发；
- 多小文件场景明显更快；设置修改后对新入队任务立即生效。

### 4. SFTP 大文件多通道并行下载（≥8 MiB）
- 把文件切块（4 MiB/块）用多条 SFTP 通道并行读取，再按偏移有序写入；
- 单大文件下载常见 2–4 倍提速（受 Wi-Fi 上限约束）。

### 5. SFTP 大文件上传改用 MINA SSHD 引擎（≥8 MiB）
- JSch 的 SFTP 窗口与数据包尺寸写死（32 KiB 包 + 固定窗口），长肥管道上吞吐被卡住；
- 改用 Apache MINA SSHD 传输引擎，窗口 4 MiB / 包 64 KiB，可配置；
- 局域网同条件 8 MiB 传输实测约 2 倍。

### 6. SCP 上传流水线
- 由「读一块、发一块、等一次确认」改为 256 KiB 读块 + 512 KiB 通道缓冲，数据阶段不再逐块等待；
- SCP 上传明显更快。

### 7. FTP/FTPS 续传缓冲修正
- 续传上传「跳过已上传前缀」时，某些流会退化为逐字节读取，现改为 128 KiB 缓冲消费。

### 8. 下载前预分配文件
- 按远端大小预分配目标文件（ftruncate），减少写入期碎片与元数据开销；
- 已处理「预分配大小 ≠ 已下载字节」的续传判断，不会误判为已完成。

### 9. socket 调优结论（实测后保留原值）
- 128 KiB vs 256 KiB 缓冲在回环测试中无稳定收益，保留 128 KiB（更低内存占用）；
- TCP_NODELAY：JSch 已默认开启；FTP 明文开启无收益、FTPS 数据连接无法安全替换，故不额外设置。

## 二、安全加固

### 1. 敏感页面禁止截屏 / 录屏（FLAG_SECURE）
以下页面加入 FLAG_SECURE，系统截图、录屏与最近任务缩略图都无法获取内容：
- 快速传文件「发送」页（展示 8 位接收码与二维码）；
- 服务器编辑页（密码输入）；
- 快捷组网页（热点名称 / 密码 / 热点二维码）。

### 2. Release 包日志剥离
- R8 在 release 构建中直接删除 Log.v/d/i/w 调用（含字符串拼接与参数求值）；
- 避免日志泄露文件路径、服务器地址、接收码等运行期信息；Log.e 保留用于崩溃诊断；
- 同时减小包体。

### 3. 显式网络安全配置
- 新增 network_security_config.xml：全局禁止明文 HTTP，仅信任系统 CA；
- 文件传输走原始 TCP/TLS（FTP/FTPS/SFTP/SCP），不受影响；FTPS 证书固定仍由应用层校验负责。

## 三、其它

- 新增协议测速脚本 scripts/speed_bench.py（FTP/FTPS/SFTP/SCP 上传+下载吞吐对比）；
- 架构文档补充「吞吐调优小结」与 socket 调优实测结论；
- 单元测试从 350 增至 437，覆盖缓存、预分配、协议顺序、多通道与 MINA 引擎。
