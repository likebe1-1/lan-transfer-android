# 两台真机测试指南

本文说明如何用两台真实 Android 手机验证 App 的「快速传文件」「本机服务器」「客户端」三种用法。

---

## 0. 准备

- 两台 Android 手机，系统 **Android 10（API 29）及以上**（本项目 minSdk 29）；
- 两台手机连接 **同一个 Wi-Fi**（同一个路由器、同一网段；不要用「访客网络」）；
  - 没有 Wi-Fi 时：手机 A 开「个人热点」，手机 B 连 A 的热点也可以（此时 A 的 IP 一般是 192.168.43.x）；
- 安装同一个 APK：`app/build/outputs/apk/release/app-release.apk`（v1.3.0）。

安装方式二选一：

1. **adb 安装**（推荐，最稳）：两台手机打开「开发者选项 → USB 调试」或用无线调试连电脑后：

   ```
   adb devices
   adb -s <手机1序列号> install -r app-release.apk
   adb -s <手机2序列号> install -r app-release.apk
   ```

2. **拷 APK 安装**：用数据线/微信/QQ 把 APK 传到手机「文件管理 → 下载」，点击安装（需要允许该来源安装未知应用）。

首次打开会弹出「请在你信任的局域网下使用」，点「我已知晓」。

## 1. 快速传文件（最推荐先试，一键互传）

### 1.1 A 发送

1. A 打开 App → 首页顶部「快速传文件」→ 点「**发送文件**」；
2. 从系统文件选择器选 1~200 个文件（照片、视频、PDF、压缩包都可以）；
3. 选择完成后进入会话页，会显示：
   - **6 位接收码**（如 `737 229`，可复制/全屏展示）；
   - 本机设备名、局域网 IP；
   - FTP / FTPS / SFTP / SCP 四个端口（都显示「运行中」）；
   - 待发送文件清单。

### 1.2 B 接收

1. B 打开 App →「快速传文件」→「**接收文件**」；
2. 「附近设备」列表里应出现 A 的设备名（下方有接收码、协议 chip、IP）；
3. 点击 A → 自动连接（默认按速度与加密兼顾 **FTPS → SFTP → SCP** 自动选一种）→ 自动开始下载全部文件；
4. 观察接收页：
   - 进度条 + `已传 / 总大小` + **百分比**；
   - **实时速度**（如 4.9 MB/s）；
   - **预计剩余时间**（如「剩余约 8 秒」）；
   - 全部完成后「已保存（N）」列出文件名，文件直接在系统 **下载（Download）根目录**（文件管理器或相册可看到，不新建子文件夹）。

### 1.3 互传（B 发给 A）

1. B 在已连接页面点「**发送文件给对方**」→ 选文件 → 等待发送完成（同样有速度/剩余时间）；
2. A 的发送页「**收到的文件**」会自动出现（每 2 秒刷新），可点「导出到下载」保存。

### 1.4 结束

- A 点「**结束会话**」（会二次确认）；B 点「断开连接」或返回。之后接收码失效，临时文件清理。

### 1.5 如果 B 的「附近设备」是空的

说明路由器/环境拦了局域网 UDP 广播（见「常见问题」），可以手动兜底：

1. 在 A 的发送页确认 IP（如 192.168.1.23）和接收码；
2. B 在「接收文件 → 手动输入」填：**对方 IP 地址** + **6 位接收码**；
3. 协议选「自动」，点「连接」（也可手动选 FTP/FTPS/SFTP/SCP 逐个验证）。

> 注意：手动输入固定按默认端口 2121/2122/2222 连接；如果 A 页面上显示的端口不是这几个（端口被占用自动换了），请在「附近设备」里连接。

## 2. 本机服务器模式（验证四个协议 + 第三方客户端）

1. A：首页 →「本机服务器」→ 设置用户名/密码（默认端口 2121/2122/2222）→ 点「开始服务器」；
2. A 页面显示访问信息：本机 IP、四种协议的连接示例、共享文件；
3. B：客户端模式首页 →「添加服务器」，**分别添加 4 个**（同一个 IP）：
   - FTP：端口 2121
   - FTPS：端口 2122（TLS 模式「显式」，证书自签名需信任）
   - SFTP：端口 2222
   - SCP：端口 2222
4. B 分别打开 4 个服务器：浏览目录、下载 A 的共享文件、上传文件到 A；
5. A 的「共享文件」刷新后应看到 B 上传的文件（A 也可「导入文件」给 B 下载）；
6. 可选：用电脑端的 FileZilla/WinSCP/命令行 `ftp`/`sftp`/`scp` 连 A 的 IP，验证标准客户端兼容。

---

## 3. 快速传文件里验证四种协议

在 B 的「接收文件 → 手动输入」里，协议下拉分别选择：

- 自动（优先 SFTP）
- FTP / FTPS / SFTP / SCP

每次连接后确认能列出并接收 A 的文件；接收页会显示「已通过 X 连接 · 设备名」。

---

## 4. 建议观察的检查点

- [ ] 两台设备能互相发现（附近设备列表出现对方）；
- [ ] 传输中显示 **进度百分比 / 实时速度 / 预计剩余时间**，且数字随传输变化；
- [ ] 大文件（如 500MB 视频）速度与剩余时间估算合理；
- [ ] 传输期间切后台/锁屏，前台服务通知保持；回来后进度继续；
- [ ] 收到的文件能在系统「下载」根目录打开，大小与源文件一致；
- [ ] 互传方向（B→A）也能成功，A 能导出到下载；
- [ ] 结束会话后接收码失效、B 再连会失败（预期）；
- [ ] 四种协议（FTP/FTPS/SFTP/SCP）在客户端模式和快速传文件手动模式都能收发。

## 5. 常见问题

| 现象 | 处理 |
| --- | --- |
| B 找不到附近设备 | 确认两台在同一 Wi-Fi；路由器关闭「AP 隔离/访客网络」；MIUI/EMUI 关闭该 App 的省电限制；仍不行就手动 IP + 接收码 |
| 手动连接失败 | 确认 IP 和 6 位码正确、A 的服务器仍在「运行中」；若 A 页面端口不是 2121/2122/2222，请用附近设备列表连接 |
| 传输中途断开 | 检查是否锁屏/省电杀掉后台（允许 App 后台运行、忽略电池优化） |
| Android 13+ 没有通知 | 首次启动前台服务时允许通知权限（设置 → 应用 → 通知） |
| 第三方客户端连 FTPS 失败 | 自签证书需要客户端允许（FileZilla：勾选「信任该证书」；WinSCP：接受）；App 自带客户端默认已允许 |
| 手机连不上同一网段 | 关闭其中一台的移动数据/VPN，确认两台 IP 前三段一致 |

## 7. 自动化测试记录（2026-11-14）

- 设备：Xiaomi 24129PN74C（Android 16，192.168.3.17）+ Xiaomi 25080RABDC（Android 16，192.168.3.32），同一 Wi-Fi「HUAWEI-03」；
- 方式：发送端 `TwoPhoneSendBridge` 真实启动快速传文件会话并输出会话信息；宿主机读取后驱动接收端 `TwoPhoneReceiveTest` 进行连接/接收/回传；
- 结果：
  - FTP、FTPS、SFTP、SCP **4/4 协议通过**；
  - 接收端 4 次均通过 UDP 局域网广播发现发送端；
  - 下载 2MB 文件大小校验一致（2097152 字节），回传文件全部出现在发送端「收到的文件」；
  - 测试完成后两台手机均安装 v1.3.0 release APK。
- 真实环境问题：两台手机最初分别连接「CMCC」和「HUAWEI-03」两个不同 Wi-Fi（恰好同网段 192.168.3.x），TCP 报 `EHOSTUNREACH`、广播收不到；切换到同一 SSID 后全部通过。
